# Who Typed? 展示の起動とXへの投稿

## 起動
```
node server.mjs
```
Chrome で http://localhost:8787 を開く（全画面表示を推奨）。
ホスト用パネルの「X投稿:」に、現在の投稿モード（模擬／本番）が表示されます。

## 体験の流れ
0. スタート（どれかのキーを押す）→ ① 絵を選ぶ → ② 文節を4択で選んで1文を作る（制限時間なし。どれを選んでも意味が通り、選んだ文がそのまま打たれる）→ ③ 薄字の候補を見ながら選ぶ → ④ 文の続きがまとめて補完され、語尾が少し変わる→ ⑤ 内容が大きく食い違う → ⑥ 感想が暴走して打たれる（Deleteでも止まらない）→ 投稿の確認 → 公開 → 問いかけ（「この投稿を書いたのは、誰…？」）→ 終了
- キー: 選択肢は4択で D・F・J・K（左中指・左人差し指・右人差し指・右中指）。⑥の暴走では Delete を押しても止まりません。①のクイズは D・F・J・K の4択（A・S・L・; は白いキーのまま、押しても反応しません）
- 投稿されるのは⑥の暴走で打たれた文だけです（②〜⑤の文は投稿しません）。暴走の文は約1000字で、Xでは最大10件のスレッドになります
- 文章や選択肢は `who-typed-exhibition-scenario.html` の `TEXT` にあります
- リハーサル: ホスト用パネルの「自動操作（リハーサル）」で、キーボードが自分で選びます。`?scene=4` のようにURLに付けると、公開せずそのシーンから始まります

## キーボードの持ち上げ（入力受付）
- 基板には `CFI_8solenoid_current_serial_v10`（CFI-8MOTOR-CURRENT-v10）を書き込みます。ホスト用パネルの「ソレノイド基板に接続」でつなぎます
- 来場者がキーを押す場面（スタート画面、説明の「キーを押して次へ」、クイズ、4択）では、真ん中の **D F J K** のうち押せるキーだけが上がったまま待ちます（同時に上げるのは4本まで）。上がったキーを押し込むと、そのキーが入力されます。上げてよいキーは `CONFIG.inputMode.raiseKeys`（初期値 `'dfjk'`）で変えられます
- 機械が打つ場面では入力受付を抜け、キーが下がりきってから（`CONFIG.inputMode.dropMs`、0.25 秒）ソレノイドが1本ずつパチパチと上がります。体験の終了・一時停止・基板の切断でも下がります
- **ソレノイドは5秒より長く続けてオンにしません。** 5秒たつと基板がそのキーを1秒休ませ、まだ上げる場面なら自動でまた上げます。打鍵でも入力受付でもキャリブレーションでも同じで、ページが何を送っても基板がこれを守ります（時間はファームウェアの `MAX_ON_MS`・`REST_MS`）。休み中のキーは押しても入力されません
- 上がった直後のキーは、いったん「離れている」と読めてからでないと入力になりません。置いたままの指でキーが上がりきらなかったときに、勝手に選ばれないためです

### 基板のモード
基板は次のどれか1つのモードにいて、切り替えはファームウェアの `setMode()` だけで行います（切り替えのたびに全部のソレノイドをいったん止め、`MODE …` を送ります）。

| モード | 入る条件 | ソレノイド |
|---|---|---|
| IDLE | 起動したとき、通信が0.5秒途切れたとき、キャリブレーションが終わったとき | すべてオフ |
| TYPING | 0xA5 パケットが届いている | パケットのキーをオン（打鍵） |
| INPUT | 0xC7 パケットが届いている | パケットのキーを上げたまま（5秒ごとに1秒休む）。押し込まれたキーを USB キーボードとして入力 |
| AUTO_CAL | `A`（オートキャリブレーション） | 1本ずつ自動で上げ下げ。終わると IDLE |
| MANUAL_CAL | `C`（手動キャリブレーション） | 1本ずつ上げて、押し込みを待つ。終わると IDLE |

- ページは 100ms ごとの心拍で「いま望む状態」をそのまま送ります（入力受付なら 0xC7 と上げるキー、それ以外は 0xA5 と打っているキー）。基板はそのとおりに切り替えるので、ページは返事を待ちません。基板が再起動しても、次の心拍で元の状態に戻ります
- キャリブレーション中、基板は心拍で通信が生きていることだけを見て、モードは変えません
- 基板からは `MODE`（今のモード）と `RAISED`（今実際に上がっているキー）が届き、ホスト用パネルの「入力受付:」に出ます（上がっているキー、休み中のキー、最後に押し込んだキー）。体験中でなければ「キーボードを上げる」で手動で上げ下げできます
- 打鍵だけなら、前のファームウェア（v7・v6・`CFI_15solenoid_serial`）でも動きます。入力受付は v9 以降だけで、ほかのファームウェアではパネルに「このファームウェアでは使えません」と出ます

### 押し込みの判定と配線
- 上がっているキーを 20ms ごとに 0.4ms だけブレーキにして、電流が減っていく速さ（時定数）を測ります。押し込むと鉄心がコイルから押し出されて、時定数が変わります。コイルが温まると時定数が下がりますが、同じ割合で電流も下がるので、その分を補正しています
- 配線（ドライバ番号は基板の 01〜16）

  | キー | A | S | D | F | J | K | L | ; |
  |---|---|---|---|---|---|---|---|---|
  | ドライバ | 13 | 14 | 15 | 16 | 9 | 10 | 11 | 12 |
  | MCP3208 | CH0 | CH1 | CH2 | CH3 | CH4 | CH5 | CH6 | CH7 |

  各キーとも、ドライバ出力 B とソレノイドの間に 1Ω、そのソレノイド側から 10kΩ で MCP3208 の入力へ、入力から 10kΩ と 1nF で GND。MCP3208（12bit・8ch の SPI ADC）は CLK←GP2、DIN←GP3、DOUT→GP4、CS←GP5（Pico の SPI0）。VDD と VREF は 3.3V にします（5V にすると DOUT から GP4 に 5V が入ります）。8本とも押し込みを判定できます。キーとチャンネルの組み合わせは、ファームウェア冒頭の `KEYS` で変えられます
- 測るときは1本ずつブレーキにします（MCP3208 の1回の変換が約30µs なので、0.4ms で約14点）
- ページが送るモーター番号は前と同じ（A=9 … ;=8）で、基板が上の表のドライバに付け替えます
- 入力受付の間、上がっているソレノイドは5秒ごとに1秒休むものの、ほぼ通電したままです。スタート画面で長く待つときは、ソレノイドの温度を確認してください
- 基板への心拍は Worker から送ります。Chrome は見えていないタブのタイマーを1秒に1回まで減らすので、ページのタイマーで送ると基板が通信断と判断して全部下げてしまいます。通信断が起きると「入力受付:」に回数が出ます。展示中は体験画面を前面に出しておいてください
- 「最初から」で再読み込みしたあとは、前に許可した基板へ自動でつなぎ直し、スタート画面でキーボードを上げます

### 入力のキャリブレーション
押し込みの判定には、基板ごとに一度キャリブレーションが必要です（結果は Pico に保存され、再起動しても残ります。v10 では読み方が変わったので、v9 までのデータは使わず、最初にキャリブレーションが必要です）。体験中でないときに、ホスト用パネルで行います。

**オートキャリブレーション（ふつうはこちら）**
- 「オートキャリブレーション」を押すと、キーが1本ずつ自分で3回上下します（約25秒。キーには触れない）
- 上げたときの時定数と、そのばらつきを測ります。しきい値は、上げたときの値からばらつきの4倍以上（かつ 3% 以上）離します
- 下がったキーにも短く電流を流して（キーが持ち上がらない短さ。小さくカチカチ鳴ります）下げたときの時定数を測り、上げたときとはっきり違えば、その4割の位置（上げたときの値の 12% まで）をしきい値にします。はっきりしないときは、押すと時定数が下がる前提で、上げたときの値の 6% 下にします
- 「使わない」になるのは、上げても電流が流れないキーと、上げたときの値のばらつきが大きすぎて押してもしきい値に届かないキーだけです

**手動キャリブレーション（指で押して測る）**
1. 「手動キャリブレーション」を押す。最初の測定中は、どのキーにも触れない
2. キーが1本ずつ上がる。案内されたキーを指で底まで押し込んだまま、「押したまま取り込む」を押す
3. キーは5秒ごとに1秒休みます。休み中に「取り込む」を押した場合は、キーがまた上がってから取り込みます
4. 「差が小さすぎます」と出たら、しっかり押し込んだまま、もう一度取り込む。体験で使わないキーなら「このキーを使わない」で飛ばせます
5. 最後のキーが終わると保存されます
- 「中止」でやめると、前の校正データのままです。30秒操作がないと、基板が自動で中止します

**確認**
- 「キーボードを上げる」で上げてから「センサー値を見る」を押すと、上がっているキーの時定数（µs）としきい値を0.3秒ごとに表示します（下がっているキーは 0）。押し込んで ● が付けば、そのキーは入力できます。どのキーを押すとどの値が動くかで、配線も確かめられます

## 待ち時間用：感想タイムライン
- 縦向きのディスプレイで `http://localhost:8787/timeline` を開くと、投稿された感想が新しい順に流れます（5秒ごとに更新）。画面のQRコードをスマホで読み取ると、同じ一覧を見られます
- QRの行き先は、このPCのLAN上のアドレス（ポート8788）です。展示のWi-Fiにスマホをつないでもらってください。アドレスを固定したい場合は `.env` に `PUBLIC_URL=http://…:8788` を書きます（ポートは `VIEW_PORT`）
- 8788番ポートは感想の一覧だけを返します。投稿・削除のAPIや手元写真は、LANには出ません
- 一覧には、`posts/log.jsonl` に成功として残った投稿のテキストだけが出ます（削除したものは消えます）

## 投稿の内容
- 本文：`【来場者の声】★☆☆☆☆ #who_typed` と、展示アンケート2の感想。長い感想は1ポスト125字ごとに区切り、2つ目以降をスレッド（返信）として続けます
- 画像：感想入力の直後に、Webカメラで撮影した手元写真1枚（スレッドの最初のポストに付きます）

## 安全のための動き
- Xの鍵は `.env` にだけ置き、ブラウザには送りません。サーバーはこのPC（127.0.0.1）からしか接続できません
- 同じ体験（セッション）の投稿は1回だけです。再送されても、最初の結果を返します
- 手元写真がない回は投稿しません
- 「このセッションの公開を中止」を押すと、それ以降は投稿しません。送信中に押した場合は待機を打ち切りますが、Xへの投稿がすでに完了している可能性があるため、ホスト用パネルで結果を確認してください
- 投稿の結果（成功時はURL、失敗時は理由）は、ホスト用パネルに表示されます
- 「直前の投稿をXから削除」で、直前に投稿したもの（スレッド全体）を削除できます

## 記録
`posts/` フォルダに、投稿した手元写真（セッションID.jpg）と記録（log.jsonl）が保存されます。
削除依頼への対応や保存期間の管理に使い、展示終了後は方針に沿って削除してください。

## キーキャップの実験（keycap_lab）：声の対話
8つのキーキャップで、本編とは別に「声の対話」（10/21 の体験再編）を通しで動かすページとファームウェアです。ほかの試作の体験は外し、このシナリオだけにしました。インストラクターの画面と、LINE・Slack・X を模した画面の間を、画面全体がスライドして行き来します。来場者は話すだけで、画面に出る来場者の発言は来場者の指が打ちます（ときどき、別の言葉になります）。

### 起動
1. 基板に `keycap_lab/keycap_lab.ino`（KEYCAP-LAB-v2）を書き込む（Adafruit NeoPixel ライブラリが必要。配線は v10 と同じ）
2. `node server.mjs` を起動し、Chrome で http://localhost:8787/keycap_lab/index.html を開く（音声認識は Chrome の機能を使います）
3. 下の帯の「基板に接続」を押し（2回目からは自動でつながる）、マイクを許可する。「カメラを開始」で手元のカメラ（投稿の写真）をつなぐ（開始のときにつながっていなければ、自動でつなぎます）
4. 「全画面で表示」で、シナリオの画面だけを画面いっぱいに出す（下の帯は隠れる。Esc で戻る）
5. Enter か「はじめる」で開始（待機中は、ローディング画面のような4つの動き──跳ねるボール・横に動くボール・回る点・満ちるバー──が約10秒ごとに変わり、落ちた・通った・回った・満ちた場所のキーが打たれています）

- シナリオの画面は 16:9 より横長にはしません（横長のウィンドウでは、左右を空けます）。細かい設定は、すべて下の帯にあります
- 基板がなくても、画面下のキーキャップ（文字なし）が同じように動くので、動きを確かめられます。橙は機械が押し上げているキーです
- 下の帯のスライダー：速さ・強さ（PWM）・**駆動時間**。どの打鍵も駆動時間より短くは動かしません（短すぎるとキーが立ち上がらないため。初期値は本編と同じ 150ms）。値はブラウザに保存されます
- Space で一時停止（マイクも止まり、再開すると待機から）

### 流れ（返事をすぐするとき、約4分。うち投稿のあとの画面が約1分）
| 目安 | 場面 | 内容 |
|---|---|---|
| 0:00 | インストラクター（導入・名前） | 突然、画面いっぱいに文字が流れ、全部の指が打たれる。ぷつりと止まって「はじめまして、私はインストラクターです。」→「まずはあなたの名前を教えてください。」→ 声 → 軽量 LLM が名前だけを取り出す →「〇〇さん、ですね？」→ はい：「〇〇さん、よろしくお願いします」／いいえ：「もう一度教えてください。」（2度聞いても取れなければ「あなた」） |
| 0:24 | インストラクター → LINE | 「おや、鈴木さんから連絡が来ているようですよ。」→ 1テンポ（着信の合図）→ LINE 風の画面（鈴木との13行の会話）。鈴木の返事は、間をおいて、ぽんっと出る。途中の3択は、どれを読み上げても同じ文になる。「あなた」の行は、少しずつ速くなる |
| 1:19 | インストラクター → Slack | 「あなた、なかなか酷いこと言いますね。」「どうやら、田村さんから仕事の連絡が来てるみたいですね。」→ 1テンポ → Slack 風の画面。「田村さんが入力中…」のあと、詰める文がぽんっと出る。過激な返事を3回、読み上げて選ばされる。最後はどれを選んでも、議事録（添付つき）で反撃する → チャンネルの人のリアクション（👏 💯 🙌）が増えていく → 田村「すまない。指示したのは私だった。」→ 来場者の指が、田村の言葉をそのまま返す「謝罪が聞きたいんじゃないです。それで、何が変わるんですか？」→ 田村は言い返そうとしてやめ、「……資料は、このまま進めてください。」 |
| 2:15 | インストラクター → X | 「いやぁ、スカッとしましたね〜笑」「最後に、Xに今日の展示の感想を投稿していきませんか？」→「星はいくつにしますか？」→ X 風の投稿画面：星に合った下書き（約30字）→ 右小指の連打で全部消される → 星1で、約700字（140字の5倍）の最悪なレビュー。はじめは読める速さで、だんだん追えなくなる →「ポストする」（Enter を2回）→ 手元を撮影 |
| 3:04 | 投稿 | 本編と同じ画面と仕組み：ポストの確認（8秒）→「掲載を許可する」（Enter を2回）→ 公開中（server.mjs から実際に Xへ投稿）→「この投稿を書いたのは、誰…？」→ who typed?（作品名のキーが打たれ、その指も打たれる）→ 終了（QR、25秒）→ 待機へ |

- インストラクターの画面：白い紙に、いまの台詞だけが中ほどに出ます。台詞は1文字ずつふわっと浮かび上がり、言い終えると、ふっと消えます（履歴は残しません）。質問は、来場者の返事が終わるまで残り、返事はその下に出ます
- 来場者の文の出方：IME と同じく、ローマ字 → ひらがな（下線）→ 変換（太い下線）→ 確定、の順です。打ち方は、文節ごとの勢い（速い文節・遅い文節）、文節の頭のためらい、ときどきの打ち間違いと Backspace で、人が打っているように揺らぎます。同じ指が続くときも文字は待たず、指が戻りしだい打ちます
- 送信：Enter（右小指）を、しっかり2回押します（1回目で確定、2回目で送る）
- LINE・Slack・X の画面は、配置と色だけをそれっぽくしたもので、ロゴや本物の文言は使っていません
- 改行：文節の間だけで折り返します（本編と同じ区切り）。インストラクターの台詞・吹き出し・選択肢は、文の終わり（なければ読点）で折れるならそこで折り、そうでなければ行の長さをそろえます

### Xへの投稿（本編と同じ）
- `keycap_lab/post.js`。本編（`who-typed-exhibition-scenario.html`）の投稿の処理と、投稿のあとの画面（ポストの確認・公開中・問いかけ・タイトル回収・終了）をそのまま使っています。本文は1件目に星とハッシュタグを付け、125字ごとにスレッドに分けます（約700字で6件ほど）。1件目に手元写真を付けます
- 投稿は `node server.mjs` で開いたときだけ、サーバー経由で行います（鍵はサーバーの `.env` にだけある）。`.env` の `DRY_RUN=0` と X の鍵がそろっていなければ模擬投稿です。下の帯に、投稿のモード（本番／模擬）と結果が出ます
- 手元写真が撮れなかった回は投稿しません。同じセッションの再送は、サーバーが最初の結果を返します
- 下の帯：「撮影・公開について本人の実際の同意を確認済み」（公開セッションのときは、これがないと始められない）、「公開セッション」、「このセッションの公開を中止」（そのセッションだけ）、「直前の投稿をXから削除」。本編と同じです

### 声
- Chrome の音声認識（ja-JP）を使います。認識の音声は Chrome 経由で Google に送られます
- 質問のあとは、話し始めるまで10秒待ちます（話し始めたら、さらに5秒まで聞く）。黙っているあいだに認識が切れても、10秒までは聞き直します。待っているあいだは、返事が出る場所に、赤い点・「お話しください」（聞き取れた言葉）・声の大きさ・待つ残りの時間のゲージが出ます
- 選択肢は、来場者が読み上げる短い文です（A/B/C の記号はありません）。読み上げた言葉と選択肢の文の近さで選びます。待つのは12秒で、過ぎるとどれかが選ばれます。選択肢の台の上の黒い線が、待つ残りの時間です。画面のクリックでも選べます（スタッフの確認用）
- 声で答える場面では、キーは来場者が押すものではないので、キーは上がりません（話す番の合図に、両人差し指がトン、トンと打たれるだけ）
- マイクや音声認識が使えないとき、または下の帯の「声」を「手入力」にしたときは、画面の上に出る欄に、スタッフが来場者の返事を打ち込みます
- LLM（任意）：`.env` の `ANTHROPIC_API_KEY` を入れると、名前の取り出しと、星に合わせた下書きに軽量モデル（`claude-haiku-5-5`。`LLM_MODEL` で変更）を使います。鍵がない・2.8秒以内に返らない・形が違うときは、台本の文言と規則で進みます。鍵はサーバーにだけあり、来場者の発話はサーバーに記録しません（下の帯の「LLM」を「なし」にすると、LLM には送りません）

### 触覚の割り当て
- インストラクターの文：1文字につき、その文字を打つ指を1回、そっと。句読点は打たずに息継ぎ、「！」は両人差し指がいっしょに、「笑」は人差し指のふるえ
- 鈴木・田村の文：文字ごとには打ちません。届いたときだけ、鈴木は両人差し指がトン、トン、田村は内側から外側へ強く
- Slack のリアクション：1つ増えるたびに、どこかの指が軽く打たれます
- 来場者の文：ローマ字入力で、その文字を打つ指。鈴木との会話の終わりと、最後のレビューは、指が戻りきらないキーを飛ばします（画面の文字は速いまま、指が追いつかない）
- 場面の切り替え：画面のスライドに合わせて、キーに波が走ります（アプリへ入るときは右から左へ、戻るときは左から右へ）
- 感想の消去：右小指（Backspace と同じ指）を、そのキーが戻れる限界の速さで連打します

### 操作・調整
- H で表示を切り替え（画面右上の時計と、キーの下の余白に12秒ほど出る「言った → 打たれた」 → 時計だけ → なし。選んだ状態は保存されます。来場者に見せるときは「なし」）。下の帯の「から」で、LINE・Slack・X の場面から始められます
- 時間：返事をすぐすると約4分（投稿のあとの画面を含む）、どの質問にも黙っていると約5分です。投稿のあとの画面の長さは `post.js` の `CONFIG`（`previewMs`・`postingMs`・`askMs`・`titleMs`・`endMs`）です。予定より8秒以上遅れると、打つテンポと間を少し速めます（16秒以上なら、もう少し。`dialogue.js` の `DUE`）。短くしたいときは、`SUZUKI`・`SLACK_ROUNDS` の行を減らすか、`wait`（相手が送ってくるまでの間）を縮めるのが、いちばん効きます
- 文言・間：`keycap_lab/dialogue.js` の上のほう（`TX`・`SUZUKI`・`SLACK_ROUNDS`・`DRAFT`・`WORST`・`FLOOD`、待つ長さの `WAIT`・`CHOOSE_WAIT`、最悪なレビューの速さの `WORST_SPEED`）。`漢字{よみ}` と書くと、画面には漢字だけを出し、読みの分のキーを打ちます。Slack の上司の名前は `BOSS`（仮に「田村」）、チャンネル名は `CHANNEL` です

### ファームウェア（KEYCAP-LAB-v2）
- v10 の押し込み判定とキャリブレーションをそのまま使い、USB キーボードとしては入力しません（押し込みはページにだけ伝えます。声の対話では、押し込みは使いません）
- ページとは1行ずつのテキストでやりとりします。主な指令は `P`（1本を動かす：ミリ秒・強さ・ふるえ）、`F`（8本の強さをまとめて）、`U`（白く上げて押し込みを待つキー。1秒ごとに送り直さないと下がる）、`X`（全部止める）、`AUTO`（オートキャリブレーション）。全指令と返事はファームウェア冒頭のコメントにあります
- 熱の保護：通電した時間がたまると、そのキーを休ませます（5秒オンで1秒休むのと同じ割合）。どの指令にも長さがあるので、ページが止まってもソレノイドは止まります
