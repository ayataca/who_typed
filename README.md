# Who Typed? 展示の起動とXへの投稿

## 起動
```
node server.mjs
```
Chrome で http://localhost:8787/who-typed-exhibition-scenario.html を開く（全画面表示を推奨）。トップの http://localhost:8787 は、keycap_lab の対話です。
ホスト用パネルの「X投稿:」に、現在の投稿モード（模擬／本番）が表示されます。

## 体験の流れ
0. スタート（どれかのキーを押す）→ ① 絵を選ぶ → ② 文節を4択で選んで1文を作る（制限時間なし。どれを選んでも意味が通り、選んだ文がそのまま打たれる）→ ③ 薄字の候補を見ながら選ぶ → ④ 文の続きがまとめて補完され、語尾が少し変わる→ ⑤ 内容が大きく食い違う → ⑥ 感想が暴走して打たれる（Deleteでも止まらない）→ 投稿の確認 → 公開 → 問いかけ（「この投稿を書いたのは、誰…？」）→ 終了
- キー: 選択肢は4択で D・F・J・K（左中指・左人差し指・右人差し指・右中指）。⑥の暴走では Delete を押しても止まりません。①のクイズは D・F・J・K の4択（A・S・L・; は白いキーのまま、押しても反応しません）
- 投稿されるのは⑥の暴走で打たれた文だけです（②〜⑤の文は投稿しません）。暴走の文は約1000字で、Xでは最大10件のスレッドになります
- 文章や選択肢は `who-typed-exhibition-scenario.html` の `TEXT` にあります
- リハーサル: ホスト用パネルの「自動操作（リハーサル）」で、キーボードが自分で選びます。`?scene=4` のようにURLに付けると、公開せずそのシーンから始まります

## キーボードの持ち上げ（入力受付）
- 基板には `CFI_8solenoid_current_serial_v10`（CFI-8MOTOR-CURRENT-v10）を書き込みます。ホスト用パネルの「ソレノイド基板に接続」でつなぎます
- 来場者がキーを押す場面（スタート画面、説明の「キーを押して次へ」、クイズ、4択）では、真ん中の **D F J K** のうち押せるキーだけが上がったまま待ちます（同時に上げるのは4本まで）。上がったキーを押し込むと、そのキーが入力されます。上げてよいキーは `CONFIG.inputMode.raiseKeys`（初期値 `'dfjk'`）で変えられます
- 機械が打つ場面では入力受付を抜け、キーが下がりきってから（`CONFIG.inputMode.dropMs`、0.25 秒）ソレノイドが1本ずつパチパチと上がります。体験の終了・一時停止・基板の切断でも下がります
- **ソレノイドは5秒より長く続けてオンにしません。** 5秒たつと基板がそのキーを1秒休ませ、まだ上げる場面なら自動でまた上げます。打鍵でも入力受付でもキャリブレーションでも同じで、ページが何を送っても基板がこれを守ります（時間はファームウェアの `MAX_ON_MS`・`REST_MS`）。休み中のキーは押しても入力されません
- 上がった直後のキーは、いったん「離れている」と読めてからでないと入力になりません。置いたままの指でキーが上がりきらなかったときに、勝手に選ばれないためです

### 基板のモード
基板は次のどれか1つのモードにいて、切り替えはファームウェアの `setMode()` だけで行います（切り替えのたびに全部のソレノイドをいったん止め、`MODE …` を送ります）。

| モード | 入る条件 | ソレノイド |
|---|---|---|
| IDLE | 起動したとき、通信が0.5秒途切れたとき、キャリブレーションが終わったとき | すべてオフ |
| TYPING | 0xA5 パケットが届いている | パケットのキーをオン（打鍵） |
| INPUT | 0xC7 パケットが届いている | パケットのキーを上げたまま（5秒ごとに1秒休む）。押し込まれたキーを USB キーボードとして入力 |
| AUTO_CAL | `A`（オートキャリブレーション） | 1本ずつ自動で上げ下げ。終わると IDLE |
| MANUAL_CAL | `C`（手動キャリブレーション） | 1本ずつ上げて、押し込みを待つ。終わると IDLE |

- ページは 100ms ごとの心拍で「いま望む状態」をそのまま送ります（入力受付なら 0xC7 と上げるキー、それ以外は 0xA5 と打っているキー）。基板はそのとおりに切り替えるので、ページは返事を待ちません。基板が再起動しても、次の心拍で元の状態に戻ります
- キャリブレーション中、基板は心拍で通信が生きていることだけを見て、モードは変えません
- 基板からは `MODE`（今のモード）と `RAISED`（今実際に上がっているキー）が届き、ホスト用パネルの「入力受付:」に出ます（上がっているキー、休み中のキー、最後に押し込んだキー）。体験中でなければ「キーボードを上げる」で手動で上げ下げできます
- 打鍵だけなら、前のファームウェア（v7・v6・`CFI_15solenoid_serial`）でも動きます。入力受付は v9 以降だけで、ほかのファームウェアではパネルに「このファームウェアでは使えません」と出ます

### 押し込みの判定と配線
- 上がっているキーを 20ms ごとに 0.4ms だけブレーキにして、電流が減っていく速さ（時定数）を測ります。押し込むと鉄心がコイルから押し出されて、時定数が変わります。コイルが温まると時定数が下がりますが、同じ割合で電流も下がるので、その分を補正しています
- 配線（ドライバ番号は基板の 01〜16）

  | キー | A | S | D | F | J | K | L | ; |
  |---|---|---|---|---|---|---|---|---|
  | ドライバ | 13 | 14 | 15 | 16 | 9 | 10 | 11 | 12 |
  | MCP3208 | CH0 | CH1 | CH2 | CH3 | CH4 | CH5 | CH6 | CH7 |

  各キーとも、ドライバ出力 B とソレノイドの間に 1Ω、そのソレノイド側から 10kΩ で MCP3208 の入力へ、入力から 10kΩ と 1nF で GND。MCP3208（12bit・8ch の SPI ADC）は CLK←GP2、DIN←GP3、DOUT→GP4、CS←GP5（Pico の SPI0）。VDD と VREF は 3.3V にします（5V にすると DOUT から GP4 に 5V が入ります）。8本とも押し込みを判定できます。キーとチャンネルの組み合わせは、ファームウェア冒頭の `KEYS` で変えられます
- 測るときは1本ずつブレーキにします（MCP3208 の1回の変換が約30µs なので、0.4ms で約14点）
- ページが送るモーター番号は前と同じ（A=9 … ;=8）で、基板が上の表のドライバに付け替えます
- 入力受付の間、上がっているソレノイドは5秒ごとに1秒休むものの、ほぼ通電したままです。スタート画面で長く待つときは、ソレノイドの温度を確認してください
- 基板への心拍は Worker から送ります。Chrome は見えていないタブのタイマーを1秒に1回まで減らすので、ページのタイマーで送ると基板が通信断と判断して全部下げてしまいます。通信断が起きると「入力受付:」に回数が出ます。展示中は体験画面を前面に出しておいてください
- 「最初から」で再読み込みしたあとは、前に許可した基板へ自動でつなぎ直し、スタート画面でキーボードを上げます

### 入力のキャリブレーション
押し込みの判定には、基板ごとに一度キャリブレーションが必要です（結果は Pico に保存され、再起動しても残ります。v10 では読み方が変わったので、v9 までのデータは使わず、最初にキャリブレーションが必要です）。体験中でないときに、ホスト用パネルで行います。

**オートキャリブレーション（ふつうはこちら）**
- 「オートキャリブレーション」を押すと、キーが1本ずつ自分で3回上下します（約25秒。キーには触れない）
- 上げたときの時定数と、そのばらつきを測ります。しきい値は、上げたときの値からばらつきの4倍以上（かつ 3% 以上）離します
- 下がったキーにも短く電流を流して（キーが持ち上がらない短さ。小さくカチカチ鳴ります）下げたときの時定数を測り、上げたときとはっきり違えば、その4割の位置（上げたときの値の 12% まで）をしきい値にします。はっきりしないときは、押すと時定数が下がる前提で、上げたときの値の 6% 下にします
- 「使わない」になるのは、上げても電流が流れないキーと、上げたときの値のばらつきが大きすぎて押してもしきい値に届かないキーだけです

**手動キャリブレーション（指で押して測る）**
1. 「手動キャリブレーション」を押す。最初の測定中は、どのキーにも触れない
2. キーが1本ずつ上がる。案内されたキーを指で底まで押し込んだまま、「押したまま取り込む」を押す
3. キーは5秒ごとに1秒休みます。休み中に「取り込む」を押した場合は、キーがまた上がってから取り込みます
4. 「差が小さすぎます」と出たら、しっかり押し込んだまま、もう一度取り込む。体験で使わないキーなら「このキーを使わない」で飛ばせます
5. 最後のキーが終わると保存されます
- 「中止」でやめると、前の校正データのままです。30秒操作がないと、基板が自動で中止します

**確認**
- 「キーボードを上げる」で上げてから「センサー値を見る」を押すと、上がっているキーの時定数（µs）としきい値を0.3秒ごとに表示します（下がっているキーは 0）。押し込んで ● が付けば、そのキーは入力できます。どのキーを押すとどの値が動くかで、配線も確かめられます

## 待ち時間用：感想タイムライン
- `http://localhost:8787/timeline`（スマホからは `http://（このPCのアドレス）:8788/timeline`）を開くと、投稿された感想が新しい順に流れます（5秒ごとに更新）。展示の横では、スマホでこの画面を開き、プロジェクタに映します
- 先頭で4秒止まってから一定の速さで下へ流れ、端で3秒止まると、ふっと先頭に戻ってくり返します（速さは `?speed=30` のように px/秒で指定）。新しい感想が届くと先頭（最新）に戻って6秒止まります。画面は消えないようにしています（対応していない端末では、自動ロックをオフにする）
- 画面の下の帯に、作品名と見出し（「Who typed?の」「来場者の声...？」）・QRコードと X のユーザー名を出します。帯は展示の案内なので、X の画面と混ざらないよう、展示画面の紙色と墨色をタイムラインと反転させて使います（ダークのときは紙色の帯、ライトのときは墨色の帯）。帯は画面の端から端まで広げ、タイムラインの列とは揃えません
- QRコードの行き先は、展示の X アカウント（`https://x.com/` ＋ `.env` の `X_HANDLE`）です。`X_HANDLE` が未設定のときは QR を出しません
- 見た目は X と同じです（アイコン・名前・@ハンドル・時刻・青いハッシュタグ・アイコン列。1回の体験のスレッドは縦線でつなぐ）。スレッドの1件目には、X と同じく手元写真が付きます。名前とアイコンは展示用フィードと同じもの（下の「名前とアイコン」）を使います
- 初期表示はライトモードです。ダークにするときは URL に `?theme=dark` を、その画面の端末の設定に合わせるときは `?theme=auto` を付けます
- 全画面（アドレスバーを消す）：展示用フィードも同じです
  - Android・iPad・PC の Chrome：開いたあと、画面を1回タップすると全画面になります（ブラウザの決まりで、最初の1回はタップが必要です）
  - iPhone：Safari は Web ページの全画面表示に対応していないので、共有ボタン →「ホーム画面に追加」で追加し、ホーム画面のアイコンから開きます。アドレスバーなしで開きます（時計などの上の帯は残ります）。トンネルの URL が変わったときは、追加し直します
  - Android も「ホーム画面に追加」から開くと、最初から全画面で開きます
- 映すスマホは、このPCのLAN上のアドレス（ポート8788）に届く必要があります。会場の Wi-Fi が端末どうしの通信を止めている場合は、USB（`adb reverse tcp:8788 tcp:8788` のあと、スマホで `http://localhost:8788/timeline`）か、スマホのテザリングに PC をつなぐ方法を使います。アドレスを固定したい場合は `.env` に `PUBLIC_URL=http://…:8788` を書きます（ポートは `VIEW_PORT`）
- 8788番ポートは、感想の一覧・フィードと、その手元写真だけを返します。投稿・削除のAPIは LAN には出ません。手元写真は、一覧に出ている回のものだけを返します（本番モードでは、実際に X に投稿された回だけ。削除した回や、公開を中止した回の写真は出ません）
- 感想タイムラインとフィードには、**X のアカウントの実際のポストだけ**が出ます（本番モードのとき）。サーバーは X からアカウントのポストを読み、それで一覧を作るので、ほかの PC で投稿した分も出て、X のアプリやサイトで消したものは出ません。新しいポストは30秒ごと（`.env` の `X_POLL_SEC`）に新しい分だけ読み、消されたものを外すため10分ごと（`X_VERIFY_MIN`）に新しい順に100件（`X_FETCH_MAX`）を読み直します。写真は X の画像をそのまま出します。感想タイムラインは【来場者の声】のポストだけ、フィードはアカウントのポストすべて（返信だけのもの・リポストは出さない）。読んだものは `posts/x_cache.json` に残し、X が読めないあいだはそれを出します（一度も読めていなければ、このPCの投稿記録から作ります）。読む回数が多すぎると X API の料金や回数の制限にかかるので、間隔は長めでもかまいません
- 一覧には、`posts/log.jsonl` に成功として残った投稿のテキストだけが出ます（削除したものは消えます）

### 大学の Wi-Fi などで、スマホから PC に届かないとき（Cloudflare Tunnel）
端末どうしの通信が止められている Wi-Fi では、スマホから `http://（このPCのアドレス）:8788` が開けません。そのときは、8788 番だけをインターネット経由で見せます。
1. `node server.mjs` を起動したまま、別のターミナルで `cloudflared tunnel --url http://localhost:8788` を実行する（初回だけ `brew install cloudflared`）
2. 表示される `https://〇〇.trycloudflare.com` に `/timeline`（または `/feed`）を付けて、スマホで開く（モバイル回線でも大学の Wi-Fi でも開ける）
3. 止めるときは、そのターミナルで `Ctrl + C`

- 公開するのは 8788 番だけです（感想・フィードと、その手元写真）。**8787 番（投稿の API がある方）は公開しません。** 8788 番は読み出しだけで、投稿・削除はできません
- アドレスを知っている人なら誰でも見られます（中身は X に投稿済みのものと同じ）。アドレスは起動するたびに変わるので、起動し直したらスマホで開き直します。PC の再起動やスリープでも切れます

## 展示用フィード（スマホで X のように流す）
- 展示のWi-Fiにつないだスマホで `http://（このPCのアドレス）:8788/feed` を開くと、展示が投稿したポストが X のプロフィール画面に近い見た目で、新しい順に自動スクロールします。アドレスはサーバー起動時に「展示用フィード」として表示されます。このPCでは `http://localhost:8787/feed` でも開けます
- 一番古いポストの次は先頭に戻ってループします。新しく投稿されると、数秒（5秒ごとに確認）でフェードして先頭に戻り、一番上に出ます
- 1回の体験のスレッドは、X と同じく縦線でつないで表示します
- 出すのは感想タイムラインと同じく、`posts/log.jsonl` に成功として残った投稿です（削除したものは消えます）。スレッドの1件目には、X と同じく手元写真が付きます。X API で読み取りはしないので、読み取りの費用はかかりません。展示を通さずに X で直接投稿したものは出ません
- 本番モード（`DRY_RUN=0`）のときは、リハーサル中の模擬投稿（X に出ていないもの）は出しません。模擬モードの間は、リハーサルで確認できるように模擬投稿も出します
- 名前とアイコン：`.env` の `X_DISPLAY_NAME`（表示名。未設定なら `X_HANDLE`）と `X_BIO`（自己紹介）を使います。このフォルダに `feed-avatar.png`（または `.jpg`）を置くとアイコンに、`feed-banner.png`（または `.jpg`、横3:縦1）を置くとヘッダー画像になります
- ダーク／ライト：最初はスマホの設定に合わせます。画面をダブルタップすると切り替わり、選んだほうはそのスマホに保存されるので、再読み込みや再起動の後もそのままです（アクセスガイド中でもタッチを有効にしておけば切り替えられます）
- 表示の調整は URL に付けます。例：`/feed?speed=60&theme=light`

  | 項目 | 初期値 | 内容 |
  |---|---|---|
  | `speed` | `40` | スクロール速度（px/秒） |
  | `theme` | `auto` | `auto`（スマホの設定に合わせる）、`dark`、`light`。ダブルタップで選んだものがあれば、そちらが優先 |
  | `startDelay` | `2` | 先頭（最新）で止まる秒数 |
  | `onNewPost` | `jump` | `jump`：新着が来たら先頭に戻る ／ `wait`：一周してから反映 |
  | `pollSeconds` | `5` | 新しい投稿を確認する間隔（秒） |
  | `reloadHours` | `6` | 長時間運用の保険として、ページを再読み込みする間隔（時間）。`0` で無効 |
  | `showTopbar` / `showProfile` | `true` | 上部の名前バー／ループ先頭のプロフィールを出すか |

- スマホの準備：ホーム画面に追加して全画面で開き、iPhone はアクセスガイド、Android はアプリ固定で操作できないようにします。自動ロックはオフにし、充電しながら置いてください
- 画面に出ている分だけを残して古い要素は消していくので、何時間流しても重くなりません。中身が変わっていない間は「変更なし」の返事だけを受け取るので、通信量もわずかです

## 投稿の内容
- 本文：`【来場者の声】★☆☆☆☆ #who_typed` と、展示アンケート2の感想。長い感想は1ポスト125字ごとに区切り、2つ目以降をスレッド（返信）として続けます
- 画像：感想入力の直後に、Webカメラで撮影した手元写真1枚（スレッドの最初のポストに付きます）

## 安全のための動き
- Xの鍵は `.env` にだけ置き、ブラウザには送りません。サーバーはこのPC（127.0.0.1）からしか接続できません
- 同じ体験（セッション）の投稿は1回だけです。再送されても、最初の結果を返します
- 手元写真がない回は投稿しません
- 「このセッションの公開を中止」を押すと、それ以降は投稿しません。送信中に押した場合は待機を打ち切りますが、Xへの投稿がすでに完了している可能性があるため、ホスト用パネルで結果を確認してください
- 投稿の結果（成功時はURL、失敗時は理由）は、ホスト用パネルに表示されます
- 「直前の投稿をXから削除」で、直前に投稿したもの（スレッド全体）を削除できます

## 記録
`posts/` フォルダに、投稿した手元写真（セッションID.jpg）と記録（log.jsonl）が保存されます。
削除依頼への対応や保存期間の管理に使い、展示終了後は方針に沿って削除してください。

## キーキャップの実験（keycap_lab）：対話
8つのキーキャップで、本編とは別に「対話」を通しで動かすページとファームウェアです。インストラクター（名乗らない）の画面と、ブラウザ・LINE・X を模した画面の間を、画面全体がスライドして行き来します。来場者の発言は来場者の指が打ちます。ところどころで、来場者がキーを押して選びます（3択）。

### 起動
1. 基板に `keycap_lab/keycap_lab.ino`（KEYCAP-LAB-v4）を書き込む（Adafruit NeoPixel ライブラリが必要。ツール → USB Stack は「Pico SDK」（初期値）のまま。配線は v10 と同じ）
2. `node server.mjs` を起動し、Chrome で http://localhost:8787 を開く（`/keycap_lab/index.html` でも開けます）
3. 下の帯の「基板に接続」を押す（2回目からは自動でつながる）。「カメラを開始」で手元のカメラ（投稿の写真）をつなぐ。カメラが複数あるときは、となりの選択欄で使うカメラを選ぶ（ブラウザに保存されます）（開始のときにつながっていなければ、自動でつなぎます）
4. 「全画面で表示」で、シナリオの画面だけを画面いっぱいに出す（下の帯は隠れる。マウスの矢印も消える。Esc で戻る）。キー入力は前面のアプリに入るので、展示中はこのページを前面に
   - Chrome のタブや Mac のメニューバーまで消すには、リポジトリの `kiosk.command` をダブルクリックして起動する（サーバーを立ち上げ、Chrome をキオスクモードで開く。終了は ⌘Q）。ふだんの Chrome とは別のプロフィールなので、基板とカメラの許可・下の帯の設定は、最初に1回やり直す
5. 待機中は、F が2秒上がって5秒下がる、をくり返します（画面にはオレンジの F。上がっているあいだは濃く光る）。**F が上がっているあいだに押し込むと、始まります**（選ぶ場面と同じ、押し込みの読み方）。Enter か「はじめる」でも始まります。基板がつながっているあいだは、キーボードの F では始まりません。時間は `dialogue.js` の `WAKE_UP_MS`・`WAKE_SLEEP_MS`

- シナリオの画面は 16:9 より横長にはしません。細かい設定は、すべて下の帯にあります
- 基板がなくても、画面下のキーキャップが同じように動き、PC のキーボードの S D F で選べ、F で始められます
- 下の帯のスライダー：速さ・強さ（PWM）・駆動時間。値はブラウザに保存されます。Space で一時停止（再開すると待機から）

選ぶ場面は、LINE 1回・ブラウジング 2回・星 1回の、合わせて4回です（どれも3択）。時間は台本どおりに動かした実測で、短くするために台本を削ってはいません。

### 選ぶ場面（3択）
- キーは S D F（左の選択肢から順に）。キーの文字（S D F など）は、来場者には関係ないので画面には出しません（画面下のキーにも出さない）
- 選択肢は、紙の下のほうに文字だけで並びます（下のほうが白くぼけて、場面の上に重なる）
- 読む時間と選ぶ時間は、はっきり分けます。まず5秒「選択肢を読んでください」：キーは上がらず、オレンジの札も、キーのオレンジも出ません。→ 5秒「選んでください」（赤い点の「入力受付中」）：キーが上がり、同時に選択肢の左にオレンジの札がぽんっと出て、札からキーへ細い線がつながり、画面下のキーもオレンジに光ります。場面の中の項目（関連する検索・インストールのボタン）にも、同じ札が付きます。中央の文は、インストラクターの台詞と同じように1文字ずつ浮かび上がり、その下の細い線がタイマーで、両はしから縮みます（読む間は黒、選ぶ間は赤）
- 押したものが、黄緑に光る枠で囲まれます（「選びました」）。勝手に決められる場面でも、画面では押したものが光るだけで、取り消しの表示はしません。そのあと場面が、決められた方へ進みます（ポインタが「無料で見る」を押す、「インストール」が押される）
- 5秒のうちに押さなければ「代わりに選びました」。決められた選択肢があればそれ、なければランダムに決まります
- 時間は `dialogue.js` の `CHOICE`（`readMs`・`selectMs` など）。キーは `CHOICE_KEYS`（3本まで）。星の選択肢は `STAR_CHOICES`

### Xへの投稿（本編と同じ仕組み）
- `keycap_lab/post.js`。投稿の処理と、投稿のあとの画面（ポストの確認・公開中・問いかけ・終了）は本編（`who-typed-exhibition-scenario.html`）と同じです（本編で黒地の画面も、ここでは白地）。本文の1件目に星とハッシュタグを付け、125字をこえるときはスレッドに分けます（いまの感想なら1件）。1件目に手元写真を付けます
- 投稿は `node server.mjs` で開いたときだけ、サーバー経由で行います（鍵はサーバーの `.env` にだけある）。`.env` の `DRY_RUN=0` と X の鍵がそろっていなければ模擬投稿です。下の帯に、投稿のモード（本番／模擬）と結果が出ます
- 手元写真が撮れなかった回は投稿しません（画面には「投稿を完了できませんでした。スタッフにお声がけください。」）。同じセッションの再送は、サーバーが最初の結果を返します
- 下の帯：「撮影・公開について本人の実際の同意を確認済み」（公開セッションのときは、これがないと始められない）、「公開セッション」、「このセッションの公開を中止」（そのセッションだけ）、「直前の投稿をXから削除」。本編と同じです
- 辛口の感想は、`dialogue.js` の `REVIEWS`（100個）を**上から順番に**使います（同じものが近くに並ばないように）。次の番号はブラウザに保存され、待機中の右上（H で表示）に「次の感想 n/100」と出ます

### LLM（任意）
- `.env` の `ANTHROPIC_API_KEY` を入れると、ほめる下書きに軽量モデル（`claude-haiku-5-5`。`LLM_MODEL` で変更）を使います。鍵がない・2.8秒以内に返らない・形が違うときは、台本の下書きで進みます。鍵はサーバーにだけあります（下の帯の「LLM」を「なし」にすると、LLM には送りません）

### 触覚の割り当て（キーが動くのは、来場者のターンだけ）
- 来場者の発言（検索ボックス・フォーム・LINE の返事・X の感想）：ローマ字入力で、その文字を打つ指。言い合いの終わりと X の感想は、指が戻りきらないキーを飛ばします
- 送信：Enter（右小指）を2回（1回目で確定、2回目で送る。`dialogue.js` の `ENTER_TWICE` を false にすると1回）
- 感想の消去：右小指を、そのキーが戻れる限界の速さで連打
- キーが動かないもの：インストラクターの台詞、相手の送信、ポインタの移動・クリック・スクロール、ポップアップ、画面の切り替え
- 例外：待機の F（上がって押されるのを待つ）と、最後の「Who typed?」

### 操作・調整
- H で、画面右上の時計（経過時間と場面）を出す／消す。下の帯の「から」で、ブラウジング・LINE・X の場面から始められます
- 文言・間：`keycap_lab/dialogue.js` の上のほう（`TX`・`B_TX`・`SUZUKI`・`DRAFT5`・`REVIEWS`、感想の速さの `REVIEW_SPEED`、待機の `SAVER_MSG`・`BEAT_MS`）。`漢字{よみ}` と書くと、画面には漢字だけを出し、読みの分のキーを打ちます

### 入力（INPUT）：キーを上げて、押し込まれたキーを受け取る
- ページで `listen('sdf')`（または `KC_INPUT.listen('sdf')`）と呼ぶと、そのキーが 80ms ずつずれて上がり、押し込みを待ちます。`listen(0)` で下げます。8本のどれでも選べますが、**同時に上げるのは3本まで**です（電源の都合。基板も3本までしか上げません）
- 押し込みは、基板が **USB キーボード**として1文字打ちます（a s d f j k l ;、小文字なので Shift なし）。ページは `keydown` で、キーの位置（`e.code`）で受け取ります。上げているキーだけを受け取り、押しっぱなしのリピートは無視します。体験は window の `kc-press` イベントで受け取ります
- ソレノイドへの指令は、今までどおりシリアルです。ページは 200ms ごとに `U`（上げるキー）を送り直し、途切れると基板は 0.5 秒で全部下げます
- 機械の打鍵は入力になりません：押しているキーと、押し終えて 150ms のあいだは読みません。コイルが切り替わった直後の 40ms は、どのキーも読みません
- 下の帯の「入力テスト」（なし／S D F／F）で、上げて試せます。右に、上げるキー・実際に上がっているキー・押せるキー・最後に押されたキー（入力していないときは、待機の鼓動の判定）が出ます
- **キー入力は前面のアプリに入ります。** 展示中は、このページを全画面で前面に出しておいてください

#### 押し込みの読み方（電流だけ。キャリブレーションは不要）
- 上げたキーのコイルは、ただオンにしておくだけです。プランジャが動くと電流が少し盛り上がるので、「速い平均（3ms）− 遅い平均（300ms）」＝揺れで読みます
- キーごとの段階：上がったところ（300ms は読まない）→（電源を入れて最初の1回だけ）揺れの測定（1.5秒。**触らない**）→ 落ち着くのを待つ（100ms）→ 押せる（しきい値を 2ms こえたら押下）→ 押下中（離した揺れか、600ms 静かで戻る）
- しきい値 = 揺れの大きさ（σ）× 6、かつ 1.0mA 以上

#### 待機の鼓動：F を押さえているか（`K` 指令。いまの対話の開始には使っていません）
- 長押しの判定は実機で安定しなかったため、対話の開始は「F を2秒上げて、押し込みを待つ」方式にしました。`K` 指令と下の仕組みは、基板と押下ビューアには残っています
- `K 3` を送ると、F を 150ms 押します。基板はそのあいだの電流を4つの区間（2–10・10–25・25–50・50–100ms）で平均し、ふだん（指で押さえていない）の鼓動の形と比べます。どこかの区間が、ふだんのばらつき × 5 をこえ、かつ 6mA 以上ずれていれば「押さえている」として、キーボードで F を打ちます（シリアルには `KNOCK 3 HELD`）
- ふだんの形は、電源を入れて最初の3回の鼓動で覚え、そのあとも「押さえていない」鼓動で少しずつ覚え直します。**電源を入れた直後の3回は、F に触れないでください**
- 実機での値はまだ確かめていません。押下ビューアの「鼓動テスト（F）」で、ふだんと押さえたときの差（1 以上で押さえている）を見て、`KSIGMAS`・`KMINMA` を合わせてください

#### 調整：押下ビューア
- `http://localhost:8787/keycap_lab/press_viewer.html` で、キーごとの揺れ・しきい値・段階・押下を見られます（シリアルは1つのページしか使えないので、keycap_lab のページは閉じる）。しきい値の倍率（`SIGMAS`）と最小値（`MINMA`）、鼓動の判定（`KSIGMAS`・`KMINMA`）を変えられます（基板の電源を切ると初期値に戻ります）

### ファームウェア（KEYCAP-LAB-v4）
- ページとは1行ずつのテキストでやりとりします。主な指令は `P`（1本を動かす）、`F`（8本の強さをまとめて）、`K`（鼓動：押さえているかを読む）、`U`（上げて押し込みを待つキー。3本まで。200ms ごとに送る）、`X`（全部止める）、`SIGMAS`・`MINMA`・`LEARN`（押下の判定）、`KSIGMAS`・`KMINMA`・`KLEARN`（鼓動の判定）、`HID 0|1`、`STREAM 1`。返事は `DOWN`・`UP`・`ARMED`・`RAISED`・`LEARNED`・`KNOCK`・`TIMEOUT` など。全指令と返事はファームウェア冒頭のコメントにあります
- 熱の保護：通電した時間がたまると、そのキーを休ませます（6秒オンで1.2秒休むのと同じ割合。ソレノイドのデータシートでは10秒まで。入力の受付は5秒）
